This page is a self-contained crash course on SQL, designed to take a learner from basic database concepts to practical querying and analytical SQL.

Read top to bottom — each level builds on the last. The course covers database fundamentals, querying and filtering, aggregation and grouping, JOINs across multiple tables, and advanced SQL such as CTEs and window functions.

The examples use small, readable tables so the focus stays on understanding how SQL works and when to use each feature.

Level 1 — database fundamentals and the basic SQL statements.

Fundamentals

We'll keep it simple, short, and practical.

Let's use one simple example throughout:

Students
+----+--------+-----+
| id | name   | age |
+----+--------+-----+
| 1  | Ali    | 24  |
| 2  | Sara   | 25  |
| 3  | Reza   | 23  |
+----+--------+-----+

1. Database

A database is a collection of organized data.

Think of it as a container that holds multiple tables.

University Database
│
├── Students
├── Courses
├── Professors
└── Enrollments

2. Table

A table stores data about one type of thing.

Students
Courses
Employees
Orders

It's similar to a spreadsheet.

3. Row

A row represents one record/entity.

1 | Ali | 24

This entire row represents one student.

4. Column

A column represents one attribute/property.

id
name
age

For example, age contains the age of every student.

5. Primary Key

A primary key uniquely identifies each row.

id | name
---+-----
1  | Ali
2  | Sara
3  | Reza

Here id is the primary key.

Rules:

  • Unique
  • Cannot be NULL
  • Identifies one specific row

6. Foreign Key

A foreign key creates a relationship between tables by referencing a key in another table.

Students
id | name
---+-----
1  | Ali
2  | Sara
Courses
id | course | student_id
---+--------+-----------
1  | SQL    | 1
2  | Python | 2

Courses.student_id is a foreign key referencing Students.id.

So:
Primary key → identifies
Foreign key → connects

7. NULL

NULL means no value / unknown value.

It is not the same as:

0
""
id | name | phone
---+------+------
1  | Ali  | NULL

Ali's phone number isn't known/provided.

8. Data Types

Every column has a type that determines what kind of data it stores.

Common ones:

INT          -- integer
VARCHAR      -- text
DECIMAL      -- decimal number
DATE         -- date
BOOLEAN      -- true/false

Example:

CREATE TABLE Students (
    id INT,
    name VARCHAR(100),
    age INT,
    birth_date DATE
);

9. CREATE TABLE

Creates a new table.

CREATE TABLE Students (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    age INT
);

10. INSERT

Adds new rows.

INSERT INTO Students (id, name, age)
VALUES (1, 'Ali', 24);

You can insert multiple rows:

INSERT INTO Students (id, name, age)
VALUES
(1, 'Ali', 24),
(2, 'Sara', 25),
(3, 'Reza', 23);

11. SELECT

Retrieves data.

SELECT * FROM Students;

* means all columns.

Or:

SELECT name, age
FROM Students;

12. UPDATE

Changes existing data.

UPDATE Students
SET age = 25
WHERE id = 1;

Important: WHERE is extremely important here. Without it, you could update every row.

13. DELETE

Deletes rows.

DELETE FROM Students
WHERE id = 1;

Again, WHERE matters. Without it:

DELETE FROM Students;

you delete all rows.

The most important thing to remember

At this stage, think of SQL as:

Database → Tables → Rows + Columns

And the four basic operations are:

OperationSQL
Get dataSELECT
Add dataINSERT
Change dataUPDATE
Delete dataDELETE

These four are the foundation of SQL.

Useful clarification from our follow-up:
You can omit age when inserting a row:

INSERT INTO Students (id, name) VALUES (1, 'Ali');

age will be NULL, assuming the column allows NULL values. If age has a DEFAULT value, that default value will be used.
SELECT + WHERE:
SELECT * chooses the columns to return; WHERE chooses the rows.

SELECT * FROM Students WHERE name = 'Ali';
UPDATE without WHERE:
UPDATE Students SET age = 25; changes the age of every row to 25.

Level 2 — querying, filtering, sorting, and inspecting data.

Querying Data

Now we get into the part of SQL you'll use constantly when working with data.

We'll keep using:

Students
+----+--------+-----+
| id | name   | age |
+----+--------+-----+
| 1  | Ali    | 24  |
| 2  | Sara   | 25  |
| 3  | Reza   | 23  |
| 4  | Mina   | 25  |
+----+--------+-----+

1. SELECT

We already saw this, but let's go one step further.

Get specific columns:

SELECT name, age
FROM Students;

Get everything:

SELECT *
FROM Students;

2. WHERE

Filters rows based on a condition.

SELECT *
FROM Students
WHERE age > 24;

Result:

Sara | 25
Mina | 25
Think:
WHERE = Which rows do I want?

Common operators:

=       -- equal
!=      -- not equal
>       -- greater than
<       -- less than
>=      -- greater than or equal
<=      -- less than or equal

3. AND

Both conditions must be true.

SELECT *
FROM Students
WHERE age > 23 AND age < 26;

4. OR

At least one condition must be true.

SELECT *
FROM Students
WHERE age = 23 OR age = 25;

5. NOT

Reverses a condition.

SELECT *
FROM Students
WHERE NOT age = 25;

This gives students whose age is not 25.

6. IN

Useful when you want to check multiple possible values.

Instead of:

WHERE age = 23 OR age = 25

you can write:

WHERE age IN (23, 25);

Much cleaner.

7. BETWEEN

Checks whether a value is within a range.

SELECT *
FROM Students
WHERE age BETWEEN 23 AND 25;

This includes 23 and 25.

8. LIKE

Used for pattern matching, mainly with text.

SELECT *
FROM Students
WHERE name LIKE 'A%';

% means any number of characters.

So this finds names starting with A:

Ali
Ahmad
Amir

Another example:

WHERE name LIKE '%a'

Names ending in a.

9. IS NULL

You cannot check NULL using:

WHERE age = NULL  -- WRONG

Instead:

WHERE age IS NULL;

Or:

WHERE age IS NOT NULL;

10. ORDER BY

Sorts your results.

Ascending:

SELECT *
FROM Students
ORDER BY age ASC;

Descending:

SELECT *
FROM Students
ORDER BY age DESC;

ASC = smallest → largest
DESC = largest → smallest

ASC is the default, so this is also valid:

ORDER BY age;

11. LIMIT

Controls how many rows you get back.

SELECT *
FROM Students
LIMIT 2;

Returns only 2 rows.

Very useful when you just want to inspect a small sample of a large table.

12. DISTINCT

Removes duplicate values.

Without DISTINCT:

SELECT age
FROM Students;
24
25
23
25

With:

SELECT DISTINCT age
FROM Students;
23
24
25

The important mental model

A very common SQL query looks like this:

SELECT name, age
FROM Students
WHERE age >= 24
ORDER BY age DESC
LIMIT 2;

Read it almost like English:

SELECT name and age
FROM Students
WHERE age is at least 24
ORDER BY age from highest to lowest
LIMIT the result to 2 rows.

SQL statements/commands include SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, and DROP.

Clauses/operators commonly used inside statements include FROM, WHERE, ORDER BY, LIMIT, GROUP BY, HAVING, JOIN, AND, OR, IN, LIKE, and BETWEEN.

Level 3 — aggregation, grouping, and filtering aggregated results.

Aggregation & Grouping

This level teaches you how to turn many rows into useful summaries. These techniques are very important for data analysis.

1. COUNT()

Counts rows or non-NULL values.

SELECT COUNT(*)
FROM Students;

Counts all rows.

You can also count a specific column:

SELECT COUNT(age)
FROM Students;

This counts non-NULL values in age.

2. SUM()

Adds numeric values.

SELECT SUM(age)
FROM Students;

In real datasets, you will use this for things such as revenue, quantities, costs, and scores.

3. AVG()

Calculates the average.

SELECT AVG(age)
FROM Students;

4. MIN() and MAX()

Find the smallest and largest values.

SELECT MIN(age), MAX(age)
FROM Students;

5. GROUP BY

Groups rows that have the same value so you can calculate something for each group.

Suppose we have:

Students
id | name | age
---+------+----
1  | Ali  | 24
2  | Sara | 25
3  | Reza | 23
4  | Mina | 25

Count students for each age:

SELECT age, COUNT(*)
FROM Students
GROUP BY age;

Result:

23 | 1
24 | 1
25 | 2
GROUP BY = make groups, then calculate something for each group.

6. HAVING

HAVING filters groups after GROUP BY.

SELECT age, COUNT(*)
FROM Students
GROUP BY age
HAVING COUNT(*) > 1;

This returns only age groups that contain more than one student.

WHERE vs HAVING

This distinction is extremely important:

ClauseWhat it filters
WHEREIndividual rows
HAVINGGroups

7. Aliases with AS

Use AS to give a column or calculation a clearer name.

SELECT AVG(age) AS average_age
FROM Students;

The important mental model

SELECT age, COUNT(*) AS student_count
FROM Students
WHERE age >= 23
GROUP BY age
HAVING COUNT(*) > 1
ORDER BY student_count DESC;
Think:
WHERE → filter rows
GROUP BY → make groups
COUNT/SUM/AVG/MIN/MAX → calculate
HAVING → filter groups
ORDER BY → sort the final result

Level 3 checklist

COUNT()
SUM()
AVG()
MIN()
MAX()
GROUP BY
HAVING
AS (aliases)

Level 4 — combining related tables and writing multi-table queries.

JOINs & Multi-Table SQL

This level teaches you how to work with multiple related tables. JOINs are one of the most important SQL skills for working with relational data.

Suppose we have:

Students
id | name
---+-----
1  | Ali
2  | Sara
3  | Reza
Courses
id | course | student_id
---+--------+-----------
1  | SQL    | 1
2  | Python | 2
3  | ML     | 1

1. INNER JOIN

INNER JOIN keeps only the rows that have a match in both tables.

In our example, Students.id matches Courses.student_id. So Ali and Sara appear because they have courses. Reza does not appear because there is no course with student_id = 3.

SELECT Students.name, Courses.course
FROM Students
INNER JOIN Courses
    ON Students.id = Courses.student_id;

Result:

Ali  | SQL
Sara | Python
Ali  | ML
Think: "Give me only the records that exist on both sides."

Question — INNER JOIN

Using the Students and Courses tables above, write a query that returns the student's name and the course name, but only for students who have at least one course.

2. LEFT JOIN

LEFT JOIN keeps every row from the left table, even when there is no match in the right table.

Here, Students is the left table. Therefore, Reza will still appear. Because he has no matching course, the course value will be NULL.

SELECT Students.name, Courses.course
FROM Students
LEFT JOIN Courses
    ON Students.id = Courses.student_id;

Result:

Ali  | SQL
Sara | Python
Ali  | ML
Reza | NULL
Think: "Keep everything from the left table, and add matching information from the right."

Question — LEFT JOIN

Using the same tables, write a query that shows every student and their course name. Students without a course must still appear.

3. RIGHT JOIN

RIGHT JOIN is the mirror image of LEFT JOIN. It keeps every row from the right table, even when there is no match in the left table.

If we write Courses RIGHT JOIN Students, every student is preserved. If we write Students RIGHT JOIN Courses, every course is preserved.

SELECT Students.name, Courses.course
FROM Students
RIGHT JOIN Courses
    ON Students.id = Courses.student_id;
Think: "Keep everything from the right table, and add matching information from the left."

Question — RIGHT JOIN

Using Students and Courses, write a query that keeps every course even if its student record does not exist.

4. FULL OUTER JOIN

FULL OUTER JOIN keeps all rows from both tables. Matching rows are combined; unmatched rows from either table are also kept, with NULL on the missing side.

So it is essentially: "Keep everything from the left and everything from the right."

SELECT Students.name, Courses.course
FROM Students
FULL OUTER JOIN Courses
    ON Students.id = Courses.student_id;

Note: Some database systems, including MySQL, do not support FULL OUTER JOIN directly. The concept is still important, and it can be reproduced with other techniques.

Question — FULL OUTER JOIN

Imagine the Students table contains a student with no course, while the Courses table contains a course whose student_id does not exist in Students. Write a query that keeps both unmatched records as well as all matches.

5. JOIN with WHERE

You can join two tables and then filter the resulting rows with WHERE.

SELECT Students.name, Courses.course
FROM Students
INNER JOIN Courses
    ON Students.id = Courses.student_id
WHERE Students.name = 'Ali';

The JOIN decides which rows can be connected; WHERE then decides which of those joined rows you want to keep.

Question — JOIN with WHERE

Write a query that joins students with their courses and returns only Sara's courses.

6. Table aliases

A table alias gives a table a short temporary name inside a query. This makes JOINs shorter and easier to read.

SELECT s.name, c.course
FROM Students AS s
JOIN Courses AS c
    ON s.id = c.student_id;

Here, s means Students and c means Courses.

AS is optional, so Students s is also valid.

Question — Table aliases

Rewrite an INNER JOIN between Students and Courses using the aliases s and c.

7. Joining more than two tables

You are not limited to two tables. You can keep adding JOINs when your data is split across several related tables.

For example, suppose Courses also has a professor_id that references Professors.id.

SELECT s.name, c.course, p.name AS professor
FROM Students AS s
JOIN Courses AS c
    ON s.id = c.student_id
JOIN Professors AS p
    ON c.professor_id = p.id;

Now the query connects three tables: Students → Courses → Professors.

Question — Joining more than two tables

Assume Courses has professor_id and Professors has id and name. Write a query that returns the student name, course name, and professor name.

8. The most important JOIN idea

JOIN connects related tables using a matching key.

Usually this means a foreign key in one table matches a primary key in another table.

INNER JOIN → only matches
LEFT JOIN → everything from the left
RIGHT JOIN → everything from the right
FULL OUTER JOIN → everything from both

LEFT JOIN
RIGHT JOIN
FULL OUTER JOIN
ON
Table aliases

Level 5 — advanced SQL patterns for analysis and reusable queries.

Advanced SQL

This level covers the SQL features that move you from basic querying toward more advanced SQL.

1. CASE

CASE lets you create conditional logic inside a query.

SELECT name,
       age,
       CASE
           WHEN age < 25 THEN 'Young'
           ELSE '25 or older'
       END AS age_group
FROM Students;

Think of it as SQL's version of if / elif / else.

2. COALESCE

COALESCE returns the first non-NULL value.

SELECT name,
       COALESCE(phone, 'Not provided') AS phone
FROM Students;

This is useful when you want a fallback value instead of NULL.

3. Subqueries

A subquery is a query inside another query.

SELECT name, age
FROM Students
WHERE age > (
    SELECT AVG(age)
    FROM Students
);

This finds students whose age is above the average age.

4. CTEs — WITH

A Common Table Expression (CTE) gives a temporary name to a query so the main query is easier to read.

WITH average_age AS (
    SELECT AVG(age) AS avg_age
    FROM Students
)
SELECT name, age
FROM Students, average_age
WHERE age > average_age.avg_age;
WITH is especially useful when a query becomes long or has multiple logical steps.

5. Window Functions

Window functions calculate across related rows without collapsing the rows into groups.

Common window functions include:

ROW_NUMBER()
RANK()
LAG()
LEAD()

6. ROW_NUMBER()

Assigns a sequential number to rows.

SELECT name,
       age,
       ROW_NUMBER() OVER (ORDER BY age DESC) AS row_num
FROM Students;

7. RANK()

Ranks rows based on a value. Tied values receive the same rank.

SELECT name,
       age,
       RANK() OVER (ORDER BY age DESC) AS age_rank
FROM Students;

8. LAG() and LEAD()

These let you access a previous or next row without joining the table to itself.

SELECT name,
       age,
       LAG(age) OVER (ORDER BY id) AS previous_age,
       LEAD(age) OVER (ORDER BY id) AS next_age
FROM Students;

9. Combining advanced features

A realistic analytical query can combine CTEs, JOINs, aggregation, filtering, and window functions.

WITH course_counts AS (
    SELECT student_id, COUNT(*) AS course_count
    FROM Courses
    GROUP BY student_id
)
SELECT s.name,
       c.course_count,
       RANK() OVER (ORDER BY c.course_count DESC) AS rank
FROM Students AS s
JOIN course_counts AS c
    ON s.id = c.student_id
ORDER BY rank;
